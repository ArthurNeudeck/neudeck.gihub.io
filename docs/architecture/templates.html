Templates and downloads

Eight Markdown templates cover every level, both Solution Blueprint profiles and decisions. Copy them into a Git repository and start with the levels your size profile needs.

Download

Template set (.zip) All eight templates and the README with rules, chapter matrix and front matter. Aurora example (.zip) Model extract, seven blueprints, nine ADRs and the findings, as Markdown.

You can also read every template in the browser; guidance comments are shown as grey boxes, diagram markers as red boxes.

Front matter

Every blueprint starts with YAML front matter. It is what the quality gate reads first: which profile to check against, which model object is described, who is accountable, who reviews.

---
blueprint: system            # enterprise | domain | dp | system | solution
profile: buy                 # enterprise | domain | dp | buy | make | solution-full | solution-light
title: ""
adoit_id: ""                 # repository ID of the described object
parent_adoit_id: ""          # next-higher level
domain: ""
digital_product: ""
status: draft                # draft | in-review | approved | archived
version: 0.1
accountable: ""              # e.g. DP Manager IT
responsible: ""              # delegated author
reviewer: ""                 # never identical to responsible
last_reviewed: YYYY-MM-DD
---

Setting up the Git repository

A layout that mirrors the levels keeps ownership obvious and lets you set code owners per folder:

blueprints/
  README.md                      # copied from the template set
  enterprise/
    enterprise-blueprint.md
    adr/                         # ADR-ENT-nnn.md
  domains/
    product-policy/
      domain-blueprint.md
      adr/
  products/
    policy-admin-nonlife/
      dp-blueprint.md
      adr/
      systems/
        novapolicy.md
        policy-adapter-layer.md
  solutions/
    active/                      # Solution Blueprints in progress
    archive/                     # returned and archived
  • ADRs live with their owning blueprint. When a Solution Blueprint returns, its ADRs move to the adr/ folder of the level that owns them.
  • ADR IDs carry the level: ADR-ENT-, ADR-DOM-, ADR-DP-, ADR-SYS-<system>-, ADR-SOL-<sb>-.
  • Code owners per folder map to the accountable roles; the reviewer rule is enforced by branch protection.

Adapting the templates

  • Keep the chapter numbers even if you drop chapters. Readers rely on chapter 2 always being the inherited constraints and chapter 11 always being risks and exceptions.
  • Replace adoit-view markers with the embedding mechanism of your repository tool.
  • Rename domains, roles and IDs freely; keep the front matter keys stable, because checks depend on them.
  • For a small company, start with the enterprise template, the System Blueprints, the ADR template and the light Solution Blueprint (see scaling).
